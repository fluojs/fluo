게시글 목록 조회, 생성, 단건 조회를 제공하는 작은 API **FluoBlog**를 만듭니다. TypeScript 기초를 알고 있으면 충분하며 Fluo 사용 경험은 필요하지 않습니다. 각 수업에서 같은 애플리케이션을 확장하고 관찰 가능한 결과를 확인한 뒤 다음으로 넘어갑니다.

이것은 초기 HTTP·DI·검증 경로를 위한 짧은 보조 실습입니다. 제품 개발과 좋은 코드 패턴, 상거래 정합성, 프레임워크 내부 구조를 이어서 배우려면 [3권 Book 시리즈](https://github.com/fluojs/fluo/blob/main/book/README.ko.md)를 읽으세요. 이 실습의 체크포인트가 책 전체의 완성 앱을 제공하는 것은 아닙니다.

## 완성할 결과

마지막에는 Node.js와 Fastify 서버에 실제 HTTP 요청을 보내고, 잘못된 입력이 거부되는 것을 확인하고, 애플리케이션 모듈을 대상으로 요청 테스트를 실행합니다. 서버를 시작하는 파일, 기능을 등록하는 모듈, 컨트롤러에 서비스를 전달하는 방법도 이해하게 됩니다.

| 수업 | 확인할 결과 |
| --- | --- |
| [앱 만들기](/ko/docs/tutorial/create-app) | starter의 `GET /health`가 `200`과 `{"status":"ok"}`를 반환합니다. |
| [첫 번째 라우트](/ko/docs/tutorial/first-route) | `GET /posts`가 첫 게시글을 반환하고 요청 테스트가 이를 확인합니다. |
| [의존성 주입](/ko/docs/tutorial/dependency-injection) | 같은 라우트가 명시적으로 등록한 서비스에서 데이터를 가져옵니다. |
| [검증과 오류](/ko/docs/tutorial/validation-errors) | 올바른 입력은 게시글을 생성하고, 잘못된 입력은 `400`, 없는 게시글은 `404`를 반환합니다. |
| [기능 전체 테스트](/ko/docs/tutorial/testing) | 요청 테스트로 생성, 조회, 오류, 애플리케이션 상태 격리를 확인합니다. |

## 하나의 환경과 애플리케이션

전체 과정에서 Node.js `>=24.0.0 <27`, pnpm **10**, TypeScript, Fastify HTTP 어댑터를 사용합니다. 터미널에서 실행하세요.

```bash
node --version
pnpm --version
```

첫 명령은 지원 범위의 Node 버전, 두 번째 명령은 `10.x` 버전을 출력해야 합니다. 다음 수업 전에 이 실행 환경을 준비하세요.

이 소개에는 이전 체크포인트가 없고 소스 수정도 필요하지 않습니다. [앱 만들기](/ko/docs/tutorial/create-app)에서 작업 디렉터리와 정확한 준비 명령을 정합니다. 이후에도 그 디렉터리를 사용하며 페이지마다 새 앱을 만들지 않습니다.

## 코드 따라가기

전체 과정에서 **하나의 애플리케이션**인 `examples/fluo-blog/00-start`를 수정합니다. `src/app.ts` 같은 경로는 이 디렉터리 기준이며 코드 제목은 `00-start/` 대상 경로를 표시합니다. **`src/app.ts`에 `AppModule`이 있습니다**. `src/app.module.ts`를 따로 만들 필요가 없습니다. `src/main.ts`는 이 모듈로 Fastify를 시작합니다.

학습 앱은 health 라우트만 있는 상태로 시작합니다. posts 기능을 추가해도 `/health`와 `/ready`를 유지하세요. 외부 CLI starter와 달리 이 학습 앱에는 greeting 기능이 없습니다. `GET /`는 상태 확인 엔드포인트가 아닙니다.

첫 번째 터미널에서 서버를 실행하고 두 번째 터미널에서 요청합니다. 수정 후에는 서버를 종료하고 `build:00`으로 빌드한 뒤 `start:00`으로 다시 시작하세요. 게시글은 데이터베이스가 아닌 **메모리**에 저장됩니다. 프로세스를 다시 시작하면 새로 생성한 게시글이 사라지고 초기 게시글만 남습니다.

## 체크포인트와 복구

전체 소스는 [`examples/fluo-blog`](https://github.com/fluojs/fluo/tree/main/examples/fluo-blog)에 있습니다. `00-start`는 직접 수정하는 앱입니다. `01-first-route`, `02-dependency-injection`, `03-validation-errors`는 비교와 복구를 위한 완성 스냅샷이므로 수정하지 않습니다. 다음 앱으로 바꿔 실행하는 것이 아니라 `00-start`에 지정된 파일을 추가·교체해 다음 스냅샷과 같은 동작을 만듭니다.

저장소 체크포인트 명령은 Fluo 저장소를 clone한 디렉터리에서 실행하며 workspace 의존성을 사용합니다. 전역 CLI로 생성한 임의의 앱에서 실행하는 명령이 아닙니다. 다음 수업에서 이 차이를 구분하며 아직 배포되지 않은 패키지 버전이 설치 가능하다고 가정하지 않습니다.

결과가 다르면 다음으로 넘어가기 전에 해당 체크포인트의 파일과 루트 모듈 import를 비교하세요. 설정 오류를 해결하려고 `experimentalDecorators`나 `emitDecoratorMetadata`를 켜지 마세요. 이 과정은 Fluo의 표준 데코레이터 도구 체인을 사용합니다.
