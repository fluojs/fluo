Data package는 모든 데이터베이스를 하나의 추상화 뒤에 숨기지 않고 storage semantics를 명시적으로 유지합니다.

| 패키지 | 사용할 때 | Deep dive |
| --- | --- | --- |
| `@fluojs/prisma` | Prisma client와 transaction context | `packages/prisma/README.ko.md` |
| `@fluojs/drizzle` | Drizzle database lifecycle과 transaction | `packages/drizzle/README.ko.md` |
| `@fluojs/mongoose` | Mongoose connection, session, request transaction | `packages/mongoose/README.ko.md` |
| `@fluojs/redis` | Redis client와 named clients | `packages/redis/README.ko.md` |
| `@fluojs/cache-manager` | HTTP/application cache contracts | `packages/cache-manager/README.ko.md` |
| `@fluojs/queue` | Redis-backed jobs와 workers | `packages/queue/README.ko.md` |

애플리케이션 기능의 storage path를 선택할 때는 [영속성](../guides/persistence)을 읽으세요.

Queue 없는 캐시 증가 또는 순수 단일 key 갱신에는 `get`/`set` 쌍 대신 [`CacheService.update`](https://github.com/fluojs/fluo/blob/main/packages/cache-manager/README.ko.md#원자-갱신)를 사용하세요. Set/delete 결정, 고정 만료 TTL, retry/오류 계약, 선택적 store capability는 패키지 README가 소유합니다. Memory는 공유 store 인스턴스 하나를 조정하며 Redis에는 canonical RedisModule DI 경로의 명시적 cache 측 `redis.atomicUpdates: true`와 원본의 single-primary/namespace 전제가 필요합니다. RedisService API나 DB 트랜잭션을 추가하거나 `remember` loader 합치기를 바꾸는 기능이 아닙니다. Drain과 metadata 운영 조건은 [운영](../guides/operations#cache-update-drain)을 참고하세요.
