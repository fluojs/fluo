Fluo's packages share a module graph, explicit dependencies and lifecycle
contracts. You can adopt the capabilities you need without treating every
package as a prerequisite.

Each guide explains the package's purpose, installation, working setup,
mechanics, defaults, failures, ownership and tests. It also shows how the
package fits into an application with its neighbors. These are explanatory
guides, not a separate generated API reference or a copy of the Book.

New to Fluo? Complete [Getting started](/docs/getting-started/quick-start) and
the [Overview](/docs/overview/modules) first. For a script or worker, read
[Standalone applications](/docs/concepts/standalone-applications).

## Application foundations

| Package | What you will learn |
| --- | --- |
| [Core](/docs/packages/core) | Standard decorators, typed tokens and module metadata |
| [Dependency injection](/docs/fundamentals/dependency-injection) | Provider resolution, visibility, scopes and overrides |
| [Runtime](/docs/packages/runtime) | Bootstrap, application contexts, readiness and shutdown |
| [Configuration](/docs/packages/config) | Validated inputs, source precedence and reload ownership |
| [Internationalization](/docs/packages/i18n) | Catalogs, locale resolution, ICU and validation messages |

Core describes a graph, DI resolves it, and Runtime runs its lifecycle.
Configuration and i18n register services in that same graph.

## Requests and representations

| Package | What you will learn |
| --- | --- |
| [HTTP](/docs/packages/http) | Request binding, routing, guards, interceptors and responses |
| [Validation](/docs/packages/validation) | DTO materialization, rule evaluation and Standard Schema |
| [Serialization](/docs/packages/serialization) | Public response shapes and committed-response boundaries |
| [OpenAPI](/docs/packages/openapi) | Describing the same routes and DTOs as an API contract |
| [GraphQL](/docs/packages/graphql) | Schema assembly, operation scope and the HTTP host |
| [React](/docs/packages/react) | Server rendering through Fluo's HTTP and DI model |

Validation controls inputs; serialization controls outputs. Neither replaces
authorization. OpenAPI describes the contract rather than executing it.

## Choose a host

| Package | Hosting model |
| --- | --- |
| [Fastify](/docs/packages/platform-fastify) | Recommended Node HTTP starter |
| [Node.js](/docs/packages/platform-nodejs) | Direct Node listener and process-owned shutdown |
| [Express](/docs/packages/platform-express) | Express hosting and native middleware boundaries |
| [Next.js](/docs/packages/platform-nextjs) | A host-owned request path without a second listener |
| [Bun](/docs/packages/platform-bun) | Native Bun server and realtime capabilities |
| [Deno](/docs/packages/platform-deno) | Native Deno serving and permissions |
| [Cloudflare Workers](/docs/packages/platform-cloudflare-workers) | Fetch lifecycle, bindings and generation ownership |

An adapter's runtime support does not make every database driver or transport
portable. Check the selected package's installation and runtime section.

[Database transactions](/docs/techniques/database-transactions) before assuming
that a database write and cache invalidation are one atomic operation.
