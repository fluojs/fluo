---
title: Serialization
description: Keep internal state out of the JSON your posts API returns.
---

Input validation protects what enters an application. Response serialization
controls what leaves it. Returning a service's internal object directly couples
the public API to every field added to that object later.

Continue after [Validation](/docs/overview/validation). Install the response
serialization package in the same generated project:

```bash
pnpm add @fluojs/serialization
```

## Verify the public shape

Run `pnpm test`, restart `pnpm dev`, and call:

```bash
curl -i http://localhost:3000/posts
curl -i -X POST http://localhost:3000/posts \
  -H 'content-type: application/json' \
  -d '{"title":"Public post","content":"Only public fields"}'
```

The list returns `200`, creation returns `201`, and each record has only
`id`, `title` and `content`. Search the response for `internalNotes`: it must be
absent even though the service stores it. The request validation from the
previous chapter must still reject invalid input.

These examples return values through the framework-managed response pipeline.
Writing directly with `context.response.send(...)` commits a response and bypasses
this interceptor's shaping. If you take ownership of writing a response, filter
its data before sending it.
