fluo is a standard-first TypeScript backend framework built on TC39 standard decorators, explicit dependency boundaries, and metadata-free runtime wiring.

## Why fluo?

Most decorator-heavy TypeScript frameworks depend on legacy compiler behavior. fluo keeps the programming model close to the JavaScript language path: no `experimentalDecorators`, no `emitDecoratorMetadata`, and no hidden reflection requirement.

## Three volumes following a growing product

[Volume 1](https://github.com/fluojs/fluo/blob/main/book/01-fluoblog/toc.md) develops a small blog into an operable service. [Volume 2](https://github.com/fluojs/fluo/blob/main/book/02-fluoshop/toc.md) adds merchandise sales to that same successful blog. [Volume 3](https://github.com/fluojs/fluo/blob/main/book/03-internals/toc.md) explores the Fluo internals and extension points that execute both products.

The Book is the primary path for learning code and backend design. The short HTTP exercise is a companion for checking the initial execution path; guides help add a specific capability to an existing application. Package READMEs and repository contracts own detailed APIs and support boundaries.

To compare frameworks first, read [Why fluo?](/en/docs/why-fluo). Start the complete learning path with [volume 1: FluoBlog](https://github.com/fluojs/fluo/blob/main/book/01-fluoblog/README.md).
