fluo는 TC39 표준 데코레이터, 명시적 의존성 경계, 메타데이터 없는 런타임 구성을 기반으로 하는 standard-first TypeScript 백엔드 프레임워크입니다.

## 왜 fluo인가요?

대부분의 데코레이터 중심 TypeScript 프레임워크는 legacy 컴파일러 동작에 의존합니다. fluo는 JavaScript 언어 경로에 가까운 프로그래밍 모델을 유지합니다. `experimentalDecorators`, `emitDecoratorMetadata`, 숨겨진 reflection 요구사항이 없습니다.

## 제품 성장 이야기로 배우는 세 권

[1권](https://github.com/fluojs/fluo/blob/main/book/01-fluoblog/toc.ko.md)은 작은 블로그를 운영 가능한 서비스로 만들고, [2권](https://github.com/fluojs/fluo/blob/main/book/02-fluoshop/toc.ko.md)은 인기를 얻은 같은 블로그에 머천다이즈 판매를 붙입니다. [3권](https://github.com/fluojs/fluo/blob/main/book/03-internals/toc.ko.md)은 앞의 두 제품을 실행하는 Fluo 내부 구조와 확장 지점을 살펴봅니다.

책은 코드와 백엔드 설계를 배우는 중심 경로입니다. 짧은 HTTP 실습은 초기 실행을 확인하는 보조 과정이고, 가이드는 기존 앱에서 특정 기능을 추가할 때 사용합니다. 상세 API와 지원 범위는 패키지 README와 저장소 계약 문서에서 관리합니다.

프레임워크를 먼저 비교하려면 [왜 fluo인가요?](/ko/docs/why-fluo)를 읽으세요. 전체 학습은 [1권 FluoBlog](https://github.com/fluojs/fluo/blob/main/book/01-fluoblog/README.ko.md)에서 시작하세요.
