Runtime adapter는 fluo application semantics와 실제 host runtime 사이의 seam입니다.

Controller, provider, guard, interceptor, validation, serialization, middleware는 fluo contract에 의존해야 합니다. Platform package는 그 contract를 Node.js server, fetch-style runtime, edge worker API로 변환합니다.

```txt
AppModule
  -> fluo runtime
  -> HTTP dispatcher
  -> platform adapter
  -> host runtime
```

Runtime target을 선택하거나 어떤 behavior가 portable하고 어떤 behavior가 adapter 책임인지 이해해야 할 때 이 가이드를 사용하세요.

## Cloudflare Worker close 소유권

Exported Cloudflare Worker `fetch` handler에는 host가 호출하는 shutdown callback이 없습니다. `worker.fetch` 밖의 application-owned trigger는 `await worker.close()`를 직접 호출할 수 있습니다. 같은 `worker.fetch` 안의 management route는 현재 response를 반환한 뒤 `executionContext.waitUntil(worker.close())` 또는 동등한 non-self-awaiting mechanism으로 close를 관찰해야 합니다. 그 안에서 await하면 자기 자신의 active request drain을 기다리다 shutdown timeout에 도달합니다. 성공한 host close는 재시작 가능합니다. 이후의 `fetch(...)`는 새 application을 만들고 bootstrap lifecycle hook을 다시 실행하며 application singleton provider를 다시 생성합니다.

## 정적 에셋

정적 에셋 policy는 애플리케이션이 `createStaticAssetsMiddleware(...)`에 `StaticAssetSource`를 제공할 때만 portable합니다. 이렇게 하면 모든 adapter에서 traversal protection, validator, `HEAD`, `Range`, `If-Range`, stream-cancellation behavior를 동일하게 유지하면서 모든 host에 filesystem이 있다고 주장하지 않습니다.

Raw Node.js, Express, Fastify에서는 `@fluojs/platform-nodejs`의 `createNodeFileSystemAssetSource(...)`를 root-confined filesystem source로 사용하세요. 이 helper는 configuration 중 invalid root를 거부하고 lexical 및 symlink escape를 거부하며 precompression을 활성화하면 `.br` 또는 `.gz` sibling을 선택할 수 있습니다. Bun, Deno, Cloudflare Workers는 애플리케이션이 소유한 source를 제공해야 하며 fluo는 해당 target에서 Node filesystem access를 emulation하지 않습니다.

## Adapter families

| Target | Package | Best for |
| --- | --- | --- |
| Fastify on Node.js | `@fluojs/platform-fastify` | High-throughput Node.js apps and server-backed realtime |
| Raw Node.js HTTP/HTTPS | `@fluojs/platform-nodejs` | Minimal dependencies and direct Node server control |
| Express | `@fluojs/platform-express` | Existing Express infrastructure and middleware familiarity |
| Bun | `@fluojs/platform-bun` | Bun-native `Bun.serve()` applications |
| Deno | `@fluojs/platform-deno` | Deno-native `Deno.serve` deployments |
| Cloudflare Workers | `@fluojs/platform-cloudflare-workers` | Edge `fetch` handlers and Worker isolate constraints |

## Portable application contract

Adapter가 달라도 fluo는 같은 framework-owned semantics를 보존합니다.

- Route metadata와 controller dispatch
- Middleware, guard, interceptor, filter, observer
- Request binding, DTO validation, response serialization
- Normalized headers, query values, params, body parsing, error envelopes
- Host가 지원하는 SSE와 streaming contract
- Lifecycle startup, shutdown, readiness/health integration

Adapter는 host-level route matching을 optimize할 수 있지만, matched request는 shared fluo dispatcher로 다시 전달되어 application behavior가 portable하게 유지됩니다.

## Next.js HEAD 라우팅

Next.js 16.x의 Node.js host에서 GET-only Fluo route에 HEAD를 연결하려면
adapter가 제공하는 opt-in을 사용합니다.

```ts
import { NextHttpApplicationAdapter } from '@fluojs/platform-nextjs';

const nextAdapter = NextHttpApplicationAdapter.create({ headRouting: 'explicit-or-get' });
```

`createNextAppRouterHandler`는 `@fluojs/platform-nextjs/app-router`에서 import합니다.
이 표준 lazy facade에서 `GET`만 export하면 Next가 자동 HEAD로 호출하고,
`HEAD`도 export하면 직접 호출합니다. 양쪽 모두 Fluo의
명시적 HEAD, ALL method wildcard, GET 순서로 route를 한 번 선택하며
handler가 반환한 404는 재시도하지 않습니다. Status와 header를 보존하면서 body를
제거하고 stream cancellation과 request cleanup을 기다립니다.
Pages Router에도 같은 adapter option을 적용합니다.

HEAD를 GET으로 재구성하던 wrapper는 제거할 수 있습니다. 이제 guard와 handler는
원래 HEAD를 보므로 기존 method 기반 분기도 수정하세요. Option 생략 시 generic
HTTP routing과 기존 adapter 기본값은 바뀌지 않습니다. Path wildcard 지원을
추가하는 기능은 아닙니다.
[Next package README](https://github.com/fluojs/fluo/blob/main/packages/platform-nextjs/README.ko.md#head-routing)가
기본값, 자원 소유권, migration 및 실제 Next E2E 검증의 소유 문서입니다.

## Fastify

Fastify는 권장 high-throughput Node.js adapter입니다.

`@fluojs/platform-fastify`에는 Node.js `>=24.0.0 <27`가 필요합니다. Node 24 미만과 Node 27+는 지원하지 않습니다.

```ts
import { FastifyHttpApplicationAdapter } from '@fluojs/platform-fastify';
import { FluoFactory } from '@fluojs/runtime';
import { AppModule } from './app.module';

const app = await FluoFactory.create(AppModule, {
  adapter: FastifyHttpApplicationAdapter.create({ port: 3000 }),
});

await app.listen();
```

`FastifyHttpApplicationAdapter.create()`는 기본 port `3000`을 사용하며 `process.env.PORT`를 읽지 않습니다. 명시한 port가 잘못되면 adapter setup 중 throw합니다.

중요한 Fastify capability:

- fluo request interface를 통한 multipart/raw-body support
- `@fluojs/websockets`용 server-backed realtime
- Shared streaming response backpressure semantics
- fluo bootstrap option을 통한 CORS, global prefix, middleware, logging
- Portability-sensitive case용 wildcard fallback이 있는 safe native Fastify route registration

```ts
const adapter = FastifyHttpApplicationAdapter.create({
  port: 3000,
  rawBody: true,
  multipart: {
    maxTotalSize: 10 * 1024 * 1024,
  },
});
```

Multipart request에서는 raw-body capture가 생략됩니다. `multipart.maxTotalSize`가 없으면 `maxBodySize`가 기본값이 되어 HTTP adapter 전반의 size limit이 portable하게 유지됩니다.

Fastify는 공유 단일 byte-range 및 `If-Range` policy를 보존합니다. Conditional-request 평가가 cache validator를 선택한 뒤 유효한 `Range: bytes=` 요청은 `206`을 만들고, `If-Range`는 선택된 validator를 재사용하며 malformed 또는 multi-range field는 전체 response를 유지하고 충족 불가능한 range는 body 없는 `416`을 만듭니다.

### Fastify HTTPS/TLS

Fastify process가 TLS를 직접 종료할 때는 Node.js `https.ServerOptions`를 `FastifyHttpApplicationAdapter.create(...)`의 `https` option으로 전달하세요.

```ts
const adapter = FastifyHttpApplicationAdapter.create({
  host: '0.0.0.0',
  https: {
    cert: tlsCertificate,
    key: tlsPrivateKey,
  },
  port: 3443,
});
```

Adapter를 만들기 전에 application configuration 또는 secret-management boundary에서 certificate material을 로드하세요. Package가 certificate file이나 environment variable을 대신 읽지 않습니다. 신뢰된 load balancer, ingress, API gateway가 TLS를 종료한다면 `https`를 설정하지 말고 해당 infrastructure boundary 뒤에서 Fastify를 일반 HTTP로 실행하세요.

## Raw Node.js

Express나 Fastify 없이 built-in `http`/`https` server primitive를 직접 사용하려면 raw Node.js adapter를 선택합니다.

`@fluojs/platform-nodejs`에는 Node.js `>=24.0.0 <27`가 필요합니다. Node 24 미만과 Node 27+는 지원하지 않습니다.

```ts
import { NodeHttpApplicationAdapter } from '@fluojs/platform-nodejs';
import { FluoFactory } from '@fluojs/runtime';
import { AppModule } from './app.module';

const app = await FluoFactory.create(AppModule, {
  adapter: NodeHttpApplicationAdapter.create({ port: 3000 }),
});

await app.listen();
```

`NodeHttpApplicationAdapter.create(options)`는 HTTPS, body-size limit, compression, multipart를 같은 객체로 받습니다.

```ts
const adapter = NodeHttpApplicationAdapter.create({
  port: 443,
  https: {
    key: fs.readFileSync('key.pem'),
    cert: fs.readFileSync('cert.pem'),
  },
  maxBodySize: 1_048_576,
  compression: true,
  multipart: { maxTotalSize: 2_097_152 },
});
```

`maxBodySize`는 raw Node request byte가 아직 streaming 중일 때 적용됩니다. 기본 request body cap은 `1 MiB`이고, 잘못된 `port` 또는 `maxBodySize`는 setup 중 throw합니다.

Factory 생성과 instance listen을 사용하고 Node의 graceful shutdown은 명시적 `shutdownRegistration` callback으로 연결합니다.

```ts
import { FluoFactory } from '@fluojs/runtime';
import { NodeHttpApplicationAdapter, createConsoleApplicationLogger, createNodeShutdownSignalRegistration } from '@fluojs/platform-nodejs';
import { AppModule } from './app.module';

const app = await FluoFactory.create(AppModule, {
  adapter: NodeHttpApplicationAdapter.create({
    port: 3000,
  }),
  globalPrefix: 'api',
  logger: createConsoleApplicationLogger(),
  shutdownRegistration: createNodeShutdownSignalRegistration(['SIGINT', 'SIGTERM']),
});
await app.listen();
```

Shutdown timeout이나 failure가 발생하면 helper는 log를 남기고 `process.exitCode`를 설정하지만, 최종 process termination은 host process가 소유합니다.

`compression` 기본값은 `false`이며 range 응답은 compression을 켜도 identity byte를 유지합니다. `multipart.maxTotalSize` 생략은 유효 `maxBodySize`를 따릅니다. 표준 startup은 위 `FluoFactory.create` 다음 `app.listen()`입니다. Host는 `app.close()`와 명시적인 process signal 등록/해제를 소유합니다.

Static adapter + `FluoFactory.create(...)` + `app.listen()`이 managed startup 경로입니다. Node signal callback을 명시적으로 선택하면 종료 timeout/failure를 log와 `process.exitCode`로 보고하고 최종 process 종료는 host가 소유합니다. [Node adapter migration](https://github.com/fluojs/fluo/blob/main/docs/getting-started/migrate-node-adapter-create.ko.md)에 따라 제거된 alias와 run helper를 이전하세요.

## Express

기존 Express-oriented environment와 통합하려면 Express adapter를 사용합니다. `@fluojs/platform-express`는 Node.js `>=24.0.0 <27`이 필요하며 listener-level RFC `QUERY`가 Express와 fluo dispatch에 도달하도록 이 정확한 `engines.node` 범위를 선언합니다. Node 24 미만과 Node 27 이상은 제외됩니다.

Express host 교체는 NestJS legacy decorator 또는 reflection metadata semantics를 유지하지 않습니다. HTTP host를 변경하기 전에 controller와 provider를 TC39 표준 데코레이터, class-level `@Inject(...)`, 명시적 DI/module wiring으로 마이그레이션하세요.

```ts
import {
  ExpressHttpApplicationAdapter,
} from '@fluojs/platform-express';
import { FluoFactory } from '@fluojs/runtime';
import { AppModule } from './app.module';

const adapter = ExpressHttpApplicationAdapter.create({ port: 3000 });
const app = await FluoFactory.create(AppModule, { adapter });

await app.listen();

const { bindTarget, url } = adapter.getListenTarget();
console.log(`Listening on ${url} (${bindTarget})`);
```

`ExpressHttpApplicationAdapter.create()`는 concrete `ExpressHttpApplicationAdapter`를 반환하므로 별도 narrow 없이 startup 이후 `getListenTarget()`을 사용할 수 있습니다. `getListenTarget()`, `getServer()`, `getRealtimeCapability()`는 infrastructure boundary에 두고 application provider는 portable 계약을 사용하세요.

Adapter는 Express application을 직접 생성하고 소유하므로 기존 Express application을 채택하거나 재사용하는 방식은 지원하지 않습니다. Native Express handler는 construction-time `nativeMiddleware`로 제공해야 하며, bootstrap 이후 `use(...)`로 native stack에 middleware를 추가하는 방식은 지원하지 않습니다. 이식 가능한 동작은 fluo `Middleware`로 재작성하는 방식을 우선하세요.

Express는 shared SSE/streaming response contract를 지원합니다.

```ts
import { Sse, SseResponse, type RequestContext } from '@fluojs/http';

@Sse('events')
async streamEvents(_input: undefined, context: RequestContext) {
  const events = new SseResponse(context);
  events.send({ data: 'hello' });
  return events;
}
```

Native Express Router match도 shared fluo dispatcher로 hand off됩니다. 따라서 middleware, guard, interceptor, observer, params, error envelope, versioning, response serialization이 보존됩니다. `/:id`와 `/:slug`처럼 모호한 route shape, `@All(...)`, `OPTIONS` ownership, duplicate-slash/trailing-slash normalization, non-URI versioning은 catch-all fallback path에 남습니다.

## Bun

Native `Bun.serve()` application에는 Bun adapter를 사용합니다.

```ts
import { BunHttpApplicationAdapter } from '@fluojs/platform-bun';
import { FluoFactory } from '@fluojs/runtime';
import { AppModule } from './app.module';

const app = await FluoFactory.create(AppModule, {
  adapter: BunHttpApplicationAdapter.create({ port: 3000 }),
});

await app.listen();
```

`Bun.serve()`를 직접 관리하고 싶다면 fetch handler를 생성합니다.

```ts
import { createBunFetchHandler } from '@fluojs/platform-bun';

const handler = createBunFetchHandler({
  dispatcher: app.getHttpDispatcher(),
});

Bun.serve({
  fetch: handler,
  port: 3000,
});
```

`createBunFetchHandler(...)`는 동기적으로 fetch bridge만 생성합니다. 이를 수동 `Bun.serve(...)` 호출에 넣는 경우 주변 Bun host가 shutdown, websocket upgrade, native `routes` acceleration을 소유합니다. fluo가 해당 lifecycle seam을 소유해야 한다면 managed Bun adapter 경로를 사용하세요.

Bun `>=1.2.3`에서는 semantically safe static/parameterized fluo route가 `Bun.serve({ routes })`로 등록될 수 있지만, matched request는 여전히 shared dispatcher로 돌아갑니다. Versioned route, `ALL` handler, same-shape conflict, normalization-sensitive path, `OPTIONS`/CORS preflight는 shared fetch path에 남습니다.

Bun WebSocket upgrade는 `@fluojs/websockets/bun`을 통해 제공되며, `listen()`이 server를 시작하기 전에 설정되어야 합니다.

Bun fetch dispatch는 공유 단일 byte-range 및 `If-Range` policy를 보존합니다. Conditional-request 평가가 cache validator를 선택한 뒤 유효한 `Range: bytes=` 요청은 `206`을 만들고, `If-Range`는 선택된 validator를 재사용하며 malformed 또는 multi-range field는 전체 response를 유지하고 충족 불가능한 range는 body 없는 `416`을 만듭니다.

## Deno

Native `Deno.serve` deployment에는 Deno adapter를 사용합니다.

```ts
import { FluoFactory } from '@fluojs/runtime';
import { DenoHttpApplicationAdapter, createDenoShutdownSignalRegistration } from '@fluojs/platform-deno';
import { AppModule } from './app.module.ts';

const app = await FluoFactory.create(AppModule, {
  adapter: DenoHttpApplicationAdapter.create({
    port: 3000,
  }),
  shutdownRegistration: createDenoShutdownSignalRegistration(),
});
await app.listen();
```

이 managed 경로는 network listener를 엽니다. 예제는 `createDenoShutdownSignalRegistration()`을 `shutdownRegistration`으로 명시하며, host가 signal을 직접 소유하면 이를 생략합니다. Network 접근 권한을 부여해 실행하세요.

```bash
deno run --allow-net main.ts
```

Signal listener 등록에는 별도의 Deno permission이 필요하지 않습니다. Adapter 자체는 environment variable을 읽지 않습니다. 애플리케이션 코드가 해당 key를 읽을 때만 `--allow-env=PORT,DATABASE_URL`처럼 범위를 제한한 권한을 추가하세요. Signal로 트리거된 애플리케이션 close 실패는 helper가 log한 뒤 swallow하며 exit status를 설정하지 않습니다. Failure-status propagation 또는 forced termination이 필요한 host는 Factory의 `shutdownRegistration`을 생략하고 signal과 shutdown을 직접 조율해야 합니다.

Host-owned `Deno.serve(...)`에는 `app.listen()` 없이 bootstrap하고 public dispatcher에서 handler를 생성합니다.

```ts
import { FluoFactory } from '@fluojs/runtime';
import { DenoHttpApplicationAdapter, createDenoFetchHandler } from '@fluojs/platform-deno';

const adapter = DenoHttpApplicationAdapter.create();
const app = await FluoFactory.create(AppModule, { adapter });
const handler = createDenoFetchHandler({
  dispatcher: app.dispatcher,
  rawBody: true,
});

Deno.serve({ port: 3000 }, handler);
```

`createDenoFetchHandler(...)`는 동기적으로 동작하며 server를 시작하지 않습니다. 주변 host가 shutdown, signal handling, websocket upgrade를 소유하고 handler는 shared cookie/query decoding, raw-body 및 multipart parsing, SSE framing을 보존합니다.

HTTPS mode로 시작하려면 TLS material을 `https` option으로 넘깁니다.

```ts
import { DenoHttpApplicationAdapter, createDenoShutdownSignalRegistration } from '@fluojs/platform-deno';
import { FluoFactory } from '@fluojs/runtime';
const app = await FluoFactory.create(AppModule, {
  adapter: DenoHttpApplicationAdapter.create({
    hostname: '127.0.0.1',
    https: {
      cert: await Deno.readTextFile('./cert.pem'),
      key: await Deno.readTextFile('./key.pem'),
    },
    port: 3443,
  }),
  shutdownRegistration: createDenoShutdownSignalRegistration(),
});
await app.listen();
```

`hostname`은 Deno-native option name입니다. `host`는 portability alias로 허용되며, 둘 다 있으면 `hostname`이 우선합니다. Dispatcher가 bind되기 전 `handle(...)`은 JSON `500`, shutdown 중에는 JSON `503`을 반환합니다.

## Cloudflare Workers

Edge `fetch` deployment에는 Workers adapter를 사용합니다.

```ts
import { CloudflareWorkerHttpApplicationAdapter } from '@fluojs/platform-cloudflare-workers';
import { FluoFactory } from '@fluojs/runtime';
import { AppModule } from './app.module';

const adapter = CloudflareWorkerHttpApplicationAdapter.create();
const app = await FluoFactory.create(AppModule, { adapter });

await app.listen();

export default {
  fetch: (req, env, ctx) => adapter.fetch(req, env, ctx),
};
```

lazy bootstrap에는 generation과 drain lifecycle을 소유하는 host를 사용합니다.

```ts
import { CloudflareWorkerApplicationHost } from '@fluojs/platform-cloudflare-workers';
import { AppModule } from './app.module';

const worker = CloudflareWorkerApplicationHost.create(AppModule);

export default {
  fetch: worker.fetch,
};
```

Workers는 server socket을 열지 않습니다. `listen()`은 `fetch(...)`가 application traffic을 받기 전에 fluo dispatcher를 binding합니다. WebSocket을 사용할 때는 bootstrap이 해당 listen boundary 전에 adapter binding을 구성하도록 runtime module을 application graph에 등록하세요.

```ts
import { Module } from '@fluojs/core';
import {
  CloudflareWorkersWebSocketModule,
  WebSocketGateway,
} from '@fluojs/websockets/cloudflare-workers';

@WebSocketGateway({ path: '/ws' })
class EdgeGateway {}

@Module({
  imports: [CloudflareWorkersWebSocketModule.forRoot()],
  providers: [EdgeGateway],
})
export class RealtimeModule {}
```

Worker fetch dispatch는 공유 단일 byte-range 및 `If-Range` policy를 보존합니다. Conditional-request 평가가 cache validator를 선택한 뒤 유효한 `Range: bytes=` 요청은 `206`을 만들고, `If-Range`는 선택된 validator를 재사용하며 malformed 또는 multi-range field는 전체 response를 유지하고 충족 불가능한 range는 body 없는 `416`을 만듭니다.

Worker request는 active HTTP, SSE body, upgraded WebSocket work를 `executionContext.waitUntil(...)`에 등록합니다. Shutdown 중 새 HTTP 및 WebSocket ingress는 JSON `503`을 받고, active work에는 bounded 10-second drain window가 주어집니다. Lazy host의 `close()`가 timeout되면 underlying drain이 settle될 때까지 shutdown gate를 유지한 뒤, 이후 request가 새 generation을 bootstrap할 수 있게 합니다.

Worker `env` object는 request별로 `request.cloudflare.env`에서 사용할 수 있습니다. 직접 `FluoFactory.create(...)`는 exported `fetch(...)`가 traffic을 처리하기 전에 module registration을 완료합니다. `CloudflareWorkerApplicationHost.create(AppModule, options)`는 `ready()`가 bootstrap을 미리 시작하지 않은 경우에만 첫 bootstrap을 시작합니다. 어느 경로든 미리 선언한 root module과 option만 module registration에 참여하고 해당 request의 `env`는 dispatch 중에 연결됩니다. 따라서 fetch-time binding은 `ConfigModule.forRoot(...)` 또는 singleton bootstrap provider를 구성할 수 없습니다. Bootstrap configuration은 module registration 전에 사용할 수 있는 값으로 제한하세요. 첫 environment가 그 configuration을 선택해야 할 때만 `CloudflareWorkerApplicationHost.create({ fromEnv })`를 사용하세요. Handler의 `RequestContext`에서 선택한 fetch-time binding을 읽고 검증하고 좁힌 뒤 application-shaped 값만 injected provider method에 전달하세요. Provider와 controller를 owning module에 등록하세요.

```ts
import { Inject, Module } from '@fluojs/core';
import { Controller, Get, type RequestContext } from '@fluojs/http';

interface WorkerEnv {
  API_KEY: string;
}

export class CatalogService {
  read(input: { apiKey: string }) {
    return { configured: input.apiKey.length > 0 };
  }
}

@Inject(CatalogService)
@Controller('/worker')
export class WorkerController {
  constructor(private readonly catalog: CatalogService) {}

  @Get('/catalog')
  readCatalog(_input: undefined, context: RequestContext) {
    const env = context.request.cloudflare?.env as Partial<WorkerEnv> | undefined;
    const apiKey = env?.API_KEY;
    if (typeof apiKey !== 'string' || apiKey.length === 0) {
      throw new Error('API_KEY Worker binding is required.');
    }

    return this.catalog.read({ apiKey });
  }
}

@Module({
  controllers: [WorkerController],
  providers: [CatalogService],
})
export class WorkerBindingsModule {}
```

## 흔한 실수

| 실수 | 더 나은 접근 |
| --- | --- |
| Adapter factory가 `process.env.PORT`를 암묵적으로 읽는다고 가정함 | Adapter 또는 bootstrap option에 port를 명시하세요. |
| Native route acceleration이 fluo semantics를 우회한다고 생각함 | Native match도 shared dispatcher로 돌아갑니다. |
| Fetch-style runtime에서 server-backed WebSocket option을 사용함 | Runtime-specific WebSocket subpath를 사용하고 Bun/Deno/Workers fetch-style binding에서 `serverBacked`를 피하세요. |
| Multipart request에서 raw body를 기대함 | Multipart request는 `rawBody`를 노출하지 않습니다. Multipart API와 limit을 사용하세요. |
| Platform helper가 process를 직접 종료한다고 가정함 | 최종 termination은 host가 소유합니다. 모든 runtime이 shutdown failure를 exit code로 보고한다고 가정하지 마세요. Deno는 signal로 트리거된 애플리케이션 close 실패를 log한 뒤 swallow하며 exit status를 설정하지 않습니다. |
| Portable app code에서 Node global에 의존함 | Runtime-specific behavior는 adapter/bootstrap code에만 두세요. |
| 기존 Express application 채택 또는 post-bootstrap `use(...)` mutation | Adapter가 Express application을 생성하게 두고, 불가피한 native handler는 construction-time `nativeMiddleware`로 전달하며, 이식 가능한 동작은 fluo `Middleware`로 재작성하세요. |
