The first-feature walkthrough now belongs to the [FluoBlog tutorial](/en/docs/tutorial). It builds one posts API through complete, executable checkpoints instead of leaving module registration, validation, or tests for you to fill in.

## Build your first feature

Start with [Create an application](/en/docs/tutorial/create-app), then continue in order:

1. [Return your first posts response](/en/docs/tutorial/first-route).
2. [Connect a module and service with explicit DI](/en/docs/tutorial/dependency-injection).
3. [Validate input and handle errors](/en/docs/tutorial/validation-errors).
4. [Prove the request behavior with tests](/en/docs/tutorial/testing).

Use the same FluoBlog project throughout. Each lesson states the required starting state, exact file changes, expected responses, and a recovery checkpoint.

## Add a feature to an existing application

If your app already runs, use the [feature structure reference](https://github.com/fluojs/fluo/blob/main/docs/getting-started/first-feature-path.md) to check module registration and file responsibilities. Use [HTTP API](/en/docs/guides/http-api), [Validation & Serialization](/en/docs/guides/validation-serialization), and [Testing](/en/docs/guides/testing) for the specific capability you are adding.

The [RealWorld API example](/en/docs/examples/realworld-api) is a separate reference application, not the next state of the tutorial project.
