## 기존 애플리케이션에 기능 추가하기

이미 실행 중인 앱이 있다면 [기능 구조 레퍼런스](https://github.com/fluojs/fluo/blob/main/docs/getting-started/first-feature-path.ko.md)에서 모듈 등록과 파일별 책임을 확인하세요. 추가할 기능에 따라 [HTTP API](/ko/docs/guides/http-api), [검증과 직렬화](/ko/docs/guides/validation-serialization), [테스트](/ko/docs/guides/testing)를 참고하세요.

### HTTP와 DI 연결 구조

다음 `users` 코드는 기존 앱의 컨트롤러·서비스·요청 DTO 연결을 보여 주는 구조 레퍼런스입니다. FluoBlog 실습의 다음 단계나 독립 실행 앱이 아닙니다. 같은 디렉터리의 `users.service.ts`에는 `create(name: string)`으로 사용자를 생성하고 `findById(id: string)`으로 사용자 또는 `undefined`를 반환하는 `UsersService`가 있다고 가정합니다.

기능 모듈의 `controllers`에 `UsersController`, `providers`에 `UsersService`를 등록하고, 앱의 루트 모듈에서 그 기능 모듈을 import해야 합니다. 아래는 `users.controller.ts`의 전체 코드입니다.

```ts
import { Inject } from '@fluojs/core';
import { Controller, FromBody, FromPath, Get, Post, RequestDto } from '@fluojs/http';

import { UsersService } from './users.service';

class CreateUserDto {
  @FromBody()
  name = '';
}

class FindUserParamsDto {
  @FromPath('id')
  id = '';
}

@Controller('/users')
@Inject(UsersService)
export class UsersController {
  constructor(private readonly users: UsersService) {}

  @Post('/')
  @RequestDto(CreateUserDto)
  create(input: CreateUserDto) {
    return this.users.create(input.name);
  }

  @Get('/:id')
  @RequestDto(FindUserParamsDto)
  findOne(input: FindUserParamsDto) {
    return this.users.findById(input.id);
  }
}
```

`@Inject(UsersService)`는 생성자에 전달할 토큰을 클래스에 명시합니다. `@RequestDto(...)`는 각 핸들러의 첫 인자에 받을 DTO를 지정합니다. `POST /users`는 `@FromBody()`로 본문의 `name`을, `GET /users/:id`는 `@FromPath('id')`로 경로의 `id`를 받습니다. 컨트롤러는 이 전송 계층의 연결을 맡고 서비스는 비즈니스 동작을 소유합니다.

### DTO 파일 분리와 검증 범위

요청 계약을 별도 파일로 관리하려면 위의 `CreateUserDto`를 `create-user.dto.ts`로 옮깁니다. 다음은 그 파일의 전체 코드입니다. 컨트롤러의 기존 클래스 선언을 제거하고 `import { CreateUserDto } from './create-user.dto';`로 대체하세요. 두 DTO를 함께 선언하거나 새 라우트를 추가하는 예제가 아닙니다.

```ts
import { FromBody } from '@fluojs/http';

export class CreateUserDto {
  @FromBody()
  name = '';
}
```

필드 초기값은 Fluo의 표준 데코레이터 도구 체인에서 컴파일 가능한 선언을 위한 것입니다. `@FromBody()`는 입력 출처를 지정할 뿐, `name`이 문자열인지 또는 비어 있지 않은지 검증하지 않습니다. 이 구조 예제에는 값 검증, 영속성, 사용자가 없을 때의 `404` 처리가 없습니다. 실제 외부 입력을 받을 때는 [검증과 직렬화](/ko/docs/guides/validation-serialization)의 `@fluojs/validation` 연결과 [입력 검증과 오류 처리 실습](/ko/docs/tutorial/validation-errors)을 참고하고, [요청 테스트](/ko/docs/tutorial/testing)로 동작을 확인하세요.

[RealWorld API 예제](/ko/docs/examples/realworld-api)는 별도 참고 애플리케이션이며 튜토리얼 프로젝트의 다음 상태가 아닙니다.
